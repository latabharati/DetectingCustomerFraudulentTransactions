About this project

What FraudShield actually is

The dataset

Built on the IEEE-CIS Fraud Detection dataset (Kaggle) — around 590,000 real e-commerce transactions, roughly 3.5% of them fraudulent. Every prediction you see in the Detect Fraud stream comes from the held-out test split, transactions the models never saw during training.

The models

Nine models across five categories, all trained on the same preprocessed features:

How "real-time" works here

The live stream replays real, historical, labeled transactions from the test set in chronological order — not synthetic data, and not an actual live payment feed (which this project doesn't have access to). It's the most honest way to demonstrate real-time-style behavior without fabricating data.

Limitations

  • This is a research/dissertation demo, not a production fraud system — no authentication, no audit logging, no rate limiting.
  • Manual entry only lets you override a handful of human-interpretable fields (amount, product code, card network/type, email domain, device type, hour of day). All other columns keep the values from whichever real transaction was loaded as a template.
  • Categories typed into the manual form that weren't seen during training are scored with frequency 0, matching how the training pipeline itself handles unseen categories.

Tech stack

Flask · scikit-learn · XGBoost · CatBoost · TensorFlow/Keras · pandas · vanilla JS + Server-Sent Events for the live stream.
